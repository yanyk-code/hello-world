# hello-world
此存储库用于练习 GitHub 流.非常适合用来练习团队协作、代码审查和持续交付的流程。

### 🔧 GitHub Flow 核心六步法

你可以按照以下六个步骤，在你的练习库中完整地走一遍流程：

1.  **第一步：创建分支 (Create a Branch)**
    *   **做什么**：从默认分支（通常是 `main`）创建一个新的、描述性的分支。
    *   **为什么**：这为你提供了一个独立、安全的工作空间，你的所有修改都不会影响到稳定的 `main` 分支。
    *   **命名建议**：使用简短、清晰的名字，例如 `feature/add-readme` 或 `fix/typo-error`。

2.  **第二步：做出修改 (Make Changes)**
    *   **做什么**：在你创建的分支上，自由地添加、编辑或删除文件。
    *   **为什么**：你可以在此进行任何实验，即使犯错也很容易恢复，因为你的修改是隔离的。
    *   **关键点**：保持每次提交（commit）都是**逻辑完整且独立**的单元。例如，修复一个错误和添加一个新功能应该分成两次提交。

3.  **第三步：提交并推送 (Commit and Push)**
    *   **做什么**：将你的修改在本地提交（commit），并推送（push）到 GitHub 上的远程仓库。
    *   **为什么**：频繁推送可以备份你的工作，并让协作者看到你的进展，方便及早获得反馈。
    *   **提交信息**：为每次提交配上清晰、描述性的信息，如 `fix: correct typo in README` 或 `feat: add user login function`。

4.  **第四步：开启拉取请求 (Open a Pull Request)**
    *   **做什么**：当你的修改准备好后，在 GitHub 上创建一个拉取请求（Pull Request），提议将你的分支合并回 `main` 分支。
    *   **为什么**：这是协作的核心。它不仅是合并请求，更是一个结构化的**代码审查和讨论平台**。
    *   **关键点**：在 PR 描述中清晰说明你做了什么、为什么这么做，这能帮助审查者快速理解。

5.  **第五步：讨论与审查 (Discuss and Review)**
    *   **做什么**：团队成员会在拉取请求下进行讨论、提出问题和建议。
    *   **为什么**：通过代码审查，可以实现知识共享、保证代码质量，并确保代码符合项目标准。如果发现问题，你可以在自己的分支上继续修改并推送，PR 会自动更新。

6.  **第六步：合并并部署 (Merge and Deploy)**
    *   **做什么**：在审查通过后，将你的分支合并到 `main` 分支。
    *   **为什么**：你的工作成果正式成为项目的一部分。合并后，通常可以立即部署。合并完成后，可以安全地删除你的特性分支，保持仓库整洁。

### 💡 关于你的练习库

针对你的练习库，可以尝试这样练习：

*   **单人练习**：你可以把自己想象成不同角色，依次创建多个分支（如 `feature/update-readme`, `fix/typo` 等），为每个分支创建独立的 PR，然后自己审查并合并。
*   **多人协作**：这是 GitHub Flow 的真正用武之地。邀请朋友一起，每个人各自从 `main` 分支创建分支进行修改，然后通过 PR 来讨论和合并各自的工作。
